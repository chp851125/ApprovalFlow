# 設計說明

## 分層

| 層 | 責任 | 依賴 |
|---|---|---|
| Domain | 實體、列舉、顯示名稱、角色與參數鍵 | 無 |
| Application | 流程引擎、表單規則、查詢、通知、報表；定義 `IRepository<T>`、`IClock`、`ICurrentUser`、`IFileStorage`、`IEmailOutbox`、`IExcelExporter` 等抽象 | Domain |
| Infrastructure | JSON 儲存、本機檔案、`.eml` 輸出、ClosedXML、範例資料產生器 | Application、Domain |
| Web | MVC、驗證與授權、篩選器、背景排程 | 全部（組合根） |

Application 層的服務不使用任何 JSON 型別。改用資料庫時，只要換掉 `DependencyInjection.AddInfrastructure` 裡的 Repository 註冊。

## JSON 儲存

- 每個實體一個檔案，例如 `employees.json`；camelCase、縮排、列舉以字串表示、中文不跳脫。
- `JsonFileRepository<T>`：
  - 啟動時載入記憶體，以鎖保護，讀取時回傳深複本，避免呼叫端改到快取。
  - 寫入時先寫暫存檔，再以 `File.Move(overwrite)` 取代原檔，程式中斷也不會留下寫一半的 JSON。
  - 每個實體都有 `Version`，更新時比對版本，不符就丟出 `ConcurrencyException`，畫面顯示「此筆資料已被其他人修改，請重新整理…」。
- 單號：`DocumentNumberService` 以行程內鎖序列化取號，`DocumentSequence` 再用 Version 保護一層，確保同時送出不會重複。若取號後剛好遇到並行衝突，該號碼會跳過（允許缺號、不會重號）。

## 流程引擎（`Application/Workflow`）

### 狀態機

```
草稿 ──送出──▶ 簽核中 ──全部關卡核准──▶ 已核准
                 ├─駁回──▶ 已駁回
                 ├─退回申請人──▶ 已退回 ──重新送出──▶ 簽核中
                 ├─撤回──▶ 已撤回 ──重新送出──▶ 簽核中
                 └─超過時效──▶ 逾時（可執行簽核中的所有動作；進入下一關後恢復為簽核中）
```

不在對照表內的「狀態 × 動作」組合一律拒絕，例如核准已核准的單據。

### 送出時展開關卡（`StepBuilder`）

1. 依單據記錄的 `TemplateId`（重新送出）或該單別目前啟用的範本（首次送出）。
2. 每個關卡：
   - 條件不符時略過（金額、天數、時數）。
   - 依來源解析簽核人。申請人一定排除；部門主管若是申請人本人，改找上層部門主管；已停用的主管會往上找。
   - 找不到簽核人時略過。
   - 與前一關簽核人相同時略過（會簽除外）。
   - 單簽卻解析出多人（例如角色），視為或簽。
3. 關卡實例存進單據，所以範本改版不影響已送出的單據。

### 動作

| 動作 | 規則 |
|---|---|
| 核准 | 單簽 / 或簽：一人同意即進下一關，其他人標為「免簽」；會簽：全部同意 |
| 駁回 | 需填意見；流程結束 |
| 退回申請人 | 需填意見；申請人修改後重新送出，流程從頭展開，並新增一個內容版本 |
| 退回上一關 | 需填意見；目前關卡重置，上一個已核准的關卡重新啟動 |
| 撤回 | 只有申請人；範本可設定某關卡之後不可撤回 |
| 加簽 | 在目前關卡之後插入一關（每張單最多 5 次）；目前簽核人仍需完成本關 |
| 轉簽 | 把本關的簽核責任交給另一人 |
| 代理 | 當天有效、適用該單別的代理設定；本人也是同關簽核人時以本人身分簽核；申請人不可代理簽核自己的單 |

每個動作都會檢查狀態機與身分、比對 Version、寫入時間軸與稽核紀錄，儲存成功後才發布事件（站內通知、Email）。事件發送失敗不影響簽核結果。

### 時效（SLA）

- 關卡時效以**工作小時**計算：09:00–12:00、13:00–18:00，扣除週末與行事曆假日，補班日照常計算。
- 背景排程 `SlaMonitorService` 依序處理：
  1. 到期前 N 小時提醒，每關一次。
  2. 超過期限改為逾時並通知。
  3. 逾時超過 M 小時自動升級給上一層主管，並重新計算期限，每關一次。
- 每日摘要以「今天是否已寄過」判斷，重複執行不會重複寄送。
- 排程與管理頁的「立即執行」共用同一把鎖。

## 安全性

| 項目 | 做法 |
|---|---|
| 登入 | Cookie 驗證 + ASP.NET Core `PasswordHasher`（PBKDF2）；連續失敗鎖定；登入端點限流（每 IP 每分鐘 20 次）；全站每 IP 每分鐘 600 次 |
| Session | 每個請求檢查帳號是否停用、SecurityStamp 是否變更（重設密碼、停用會立即登出）；角色異動即時生效 |
| 授權 | 預設所有頁面都要登入；管理頁以角色原則保護；服務層再檢查一次（例如只有系統管理員能指派管理員角色、只能操作自己的通知） |
| CSRF | 全域 `AutoValidateAntiforgeryToken`；防偽 Cookie 使用 SameSite=Strict |
| 標頭 | 嚴格 CSP（只允許本站資源，沒有 `unsafe-inline`）、X-Frame-Options DENY、nosniff、Referrer-Policy、Permissions-Policy、COOP / CORP；已登入頁面 `no-store`；不輸出 Server 標頭；正式環境 HSTS + HTTPS 轉址 + Secure Cookie |
| 附件 | 副檔名白名單（系統參數也禁止設定 exe、js、html、svg 等）、大小與數量上限、檔頭檢查、隨機檔名、檔名清理、只能以下載方式取得且需有檢視權限 |
| 輸出 | Razor 自動編碼；Email 標頭移除換行（防標頭注入）；Excel 文字以字串型別寫入（不會被當成公式） |
| 重新導向 | 只接受站內網址 |
| 錯誤 | 正式環境只顯示友善錯誤頁與追蹤編號，詳細內容只寫入日誌 |
| 稽核 | 登入成功 / 失敗、鎖定、資料異動（含欄位前後值）、簽核動作、匯出、排程、重設資料 |

## 已知限制與可延伸方向

- **單一程序**：JSON 儲存與取號鎖都在單一程序內有效，不適合多台伺服器同時寫入。改用資料庫時，取號請改用交易或 Sequence。
- **資料量**：資料全部載入記憶體，適合數萬筆以內；報表與清單查詢在記憶體中進行。
- **Email**：目前只寫出 `.eml`。實作 `IEmailOutbox` 的 SMTP 版本即可真的寄出。
- **背景排程**：只在網站執行時運作，沒有分散式鎖；排程狀態存在記憶體，重新啟動後歸零。
- **加班與請假**：跨日加班、跨年度請假需分開申請。
- **金鑰**：Data Protection 金鑰以明文檔案存放在 `App_Data/keys`；正式環境建議改存到受保護的位置或加上憑證保護。
- **AllowedHosts**：預設為 `*`，部署時請改成實際網域。
